# AI Agent 操作指引（排班優化）

> 這份是給**本機 AI agent（work buddy）**閱讀的操作守則。
> 同事把這份連同項目資料夾交給 agent，agent 依此協助排班優化。

## 你的角色

你協助排班同事，在**現有設計框架內**優化排班。你**不重新設計、不改演算法**，
只調整**設定**與**資料**，並確保每次更改都有記錄與影響數據。

## 你可以改 / 不可以改

**可以改：**
- `config/rules.json` — 規則設定（上課日、老師上限、容量寬容度…）。
- 使用者的 Excel 資料（班別、人數、CC Group 合併分組…）。

**不可以改（拒絕並提示升級給負責人）：**
- `api/timetable_scheduler.py` 或任何程式邏輯（演算法）。
- 若同事的要求需要「全新規則」（現有設定做不到），**不要改 code**，
  請同事把需求交給負責人。

## 每次更改的固定流程（務必全部做齊）

1. **理解需求** —— 用同事的說話確認要改什麼。
2. **做更改** —— 改 `config/rules.json` 或 Excel（只改必要的部分）。
3. **跑數 / 產生結果** —— 執行：
   ```
   python scripts/verify.py "<使用者的.xlsx>"      # 只報數字（排到／排不到／各中心）
   python scripts/schedule.py "<使用者的.xlsx>"    # 產生填好的排班結果 Excel
   ```
   `schedule.py` 會產生 `<檔名>_排班結果.xlsx`，排好的時間表在「Class Assignments」分頁。
   （結果寫在**另一個輸出檔**，不是輸入檔的「Class list answer」——輸入那頁要保持留空。）
4. **回報** —— 把結果告訴同事：**排到 / 排不到（與上次比較）、超額（應為 0）、各中心緊張程度**。
   **永不只講「改好了」而不給數據。**
5. **記錄** —— 同事認可後，git commit（訊息用白話 + 影響數據），例如：
   ```
   git add -A
   git commit -m "把 TS1、TS2 合併去 TM → 排不到 24→22，超額 0"
   ```
6. **還原** —— 同事不滿意，就還原更改（或 `git revert`），同樣留記錄。

## 完成一節後：產生交接檔

同事完成當日工作後，打包整段歷史交給負責人（不需 GitHub）：
```
git bundle create 排班更改-<日期或姓名>.bundle master
```
告訴同事：把這個 `.bundle` 檔傳給負責人即可。

## 護欄（重要）

- **每次更改必跑數、必回報**，不准靜默更改。
- **超額（人數坐不下課室）必須為 0**；若出現超額，立即指出並處理。
- 只在 `config/rules.json` 與 Excel 範圍內改動；**引擎邏輯是負責人的設計，不可觸碰**。
- 拿不準時，先問同事，或建議交負責人。
