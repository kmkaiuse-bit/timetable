# 示範腳本 — 三拍：做出工具 → 講思路 → 教改 parameter

> **Steven 的實際做法（＝這份腳本的骨）**：
> 用 workbuddy ＋ 一份完整 PRD，做出了一個**本機版的小工具**；
> 台上要做三件事 ——
> **① 給大家看這個工具（順帶講它怎樣來） → ② 講我的思路（progression） → ③ 教大家點改 parameter（改 input Excel 就得）。**
>
> 誠實框架（可以照直講）：**PRD 是我自己寫的**（workbuddy 幫手整理需求，我再深化）；**工具是我用 workbuddy ＋ 這份 PRD 一步步做出來的**。不誇大、不遮掩。

---

## 開場：先亮一條線（30 秒）

> 「我這一 part，想同大家行一次我排時間表的思路——由一堆會議記錄，去到一個**改一改就幾秒重排好**的小工具。大家跟住條線睇就得。」

**一張 slide，五格進程，逐格點亮（點亮本身＝校長想看的 progression）：**

```
①  一堆亂        →  ②  整理成完整需求      →  ③  變成一個本機小工具     →  ④  我的思路          →  ⑤  你識改就用到
   會議記錄           workbuddy 幫手整理          我用 workbuddy ＋ 這份         點解係「整理需求 ＋       改 input Excel
   ＋ Jo 答案         ＋ 我自己深化成 PRD         PRD 一步步做出來              建工具」，唔係即場估      幾秒出新版
```

## 拍一：走一次進程 ①→③（Part 2 主體，約 6–7 分鐘）

### ① 一堆亂（30 秒）
**動作**：打開 `scheduling-meeting-v2`（會議記錄）＋ `questions-for-jo`（Jo 十八條答案），掃一掃就收。
**講稿**：
> 「規則一開始是這樣的：一份開會記錄，加 Jo 逐條答的十八個問題。散、亂、口語。第一步不是急住排，是先整理清楚。」

### ② 整理成完整需求（workbuddy 現場 run ＋ 我深化，2–3 分鐘）
> 這格＝校長熟悉、人人做到的「寫個 prompt」。做得漂亮，給校長 face。

**動作**：
1. workbuddy 上載限制文件 `timetable-constraints.md`，貼主提示（見下），送出，show 出來的 PRD。
2. 一句接落去：「我在這基礎上，自己補完、寫成一份更完整的需求。」再 show `PRD-timetable-scheduler.md`（有四檢視、重排流程那份）。

**主提示（照貼）**：
```
我上載了一份「排班限制文件」，這是我和同事開會後定下的規則。
請先完整閱讀這份文件，然後整理成一份清晰的需求文件（PRD），包含：
目標、輸入資料、限制條件（分「硬性」和「彈性」）、輸出、以及資料改動時如何處理。
限制條件請依文件內容用表格列出。
若文件中有標示「待確認」或規則有變化的項目，請另立一欄註明，方便日後跟進。
```

**講稿**：
> 「我把整份限制餵給 workbuddy，叫它整理成需求文件——硬性、彈性限制分好類，例外、待確認都列了出來。整理需求這件事，AI 真的好用，Ada 頭先示範的方法也是這樣。
> 我再自己在上面補完、寫成一份更完整的需求，把每個檢視、改動怎樣處理都寫清楚。這份 PRD 是我自己執的。」

### ③ 變成一個本機小工具（1–2 分鐘，show 成品）
**動作**：打開那個**本機版小工具**，上載一份 Excel，出完整時間表，快速走一遍：
- 四個檢視：日（課室×時段）／週·課室／週·教師（撞堂紅色標出）／月·學期曆（標香港公眾假期）
- **Issues 面板**：排不到 / 要人手睇的，全部明明白白列出，不收埋。

**講稿**：
> 「然後我用 workbuddy，配住這份 PRD，一步步把它做成一個**在我部電腦行到的小工具**。一份 Excel 上去，一份完整時間表出來——可以用課室睇、用老師睇、用整個學期的月曆睇。排不到或者要人手判斷的，它全部列在這裏，不會藏起來呃你話搞掂晒。」

**注意（紅線）**：叫它「小工具 / 小程式」就好，**不要**講 web app、技術架構、演算法、LLM。show 的是「做到什麼」，不是「點整」。

## 拍二：講我的思路（progression 的靈魂，2–3 分鐘 ★）

> 用 **Yes, and**，不用 No, but。校長方向（prompt 整理需求）是對的；我只是「行多一步」。

**講稿（逐句斟酌過）**：
> 「大家可能會問：點解要多整一個工具，唔係開個對話叫 AI 即場幫我排咩？
>
> 我條思路係咁：**整理需求，AI 真係好叻**——頭先那步就係。但時間表這樣東西，特別在意三件事：要**準**、每學期要**重複做**、而且**不可以出錯**。所以我不太想每次都叫 AI 即場估一個答案給我——今次估成這樣，下次可能估成另一樣。
>
> 於是我行多一步：**把整理好的需求，變成一件穩定的工具**。同一份輸入、同一套規則，出來的結果**每次一致**、信得過。整理需求用 AI，穩定執行就交給工具——**AI ＋ 工具**，一齊做。」

**紅線提醒**：只講穩定性的**好處**（準、快、每次一致、改完即刻重排）。**不要**講 deterministic、演算法、LLM。

---

## 拍三：教你改 parameter（empowerment 收結 ＋ 改動重頭戲，3–4 分鐘 ★）

> 校長點名要的結尾。核心訊息：**你哋唔使識砌，識改 Excel 就用到、就改到。**

**動作**：
1. 停在「舊版」時間表：「這是現在這一版。」
2. 打開 **input Excel**，指着它：「大家要掂的，只有這一份 Excel——這就是它的 parameter。」
3. 改一格（**二選一，排練熟一個**）：
   - 改人數：某班學生人數加上去，多過原本課室座位 → 觸發換室 / Issues。
   - 改開科：加開一班 → 影響老師 loading、課室。
4. 存檔 → 重新上載 → **數秒**，新版出來。前後對比：邊幾班郁咗、Issues 有無新項。

**講稿**：
> 「最後我想教大家一件事——用這個工具，其實你只需要識改**一份 Excel**。
>
> 假設下星期 Jo 話：這班多收了人，或者要加開一科。你唔使識任何嘢，只要在這份 Excel 改返那一格……（改、存檔、重新上載，等幾秒）……新版就出來了。
>
> 留意兩點：第一，它**幾秒**就重排好；第二，**同一套規則**，所以新版一樣可靠，不是重新猜一次。改完即刻知道有無新衝突。
>
> 所以這套嘢，唔係得我一個用得到——**大家識改 Excel，就用得到、改得到。**」

**收結（扣回開場那條線，順勢交棒 Part 3）**：
> 「由一堆會議記錄，到一份需求，到一個改份 Excel 就幾秒重排好的工具——這就是我這 part 想同大家行的思路。整理需求那步，大家用 Gemini、workbuddy 都做得到；把它變成一件人人改得到的工具，就是我們可以一齊再行多一步的地方。」
