# HKIT 自動排時間表工具 — 需求文件 (PRD)

## 1. 目標 Overview

每個學期開課前，HKIT 須為多個校區、上百班課編排一份完整時間表。目前以人手處理，限制眾多、容易出錯，而且每學期都要從頭再做。

本工具的目標：**輸入一份 Excel（班別、教師、課室），自動排出一份滿足所有硬限制的完整時間表，列出所有無法安排或需要人手判斷的項目，並可在人數或開科變動後於數秒內重新編排。**

一句定義：*Given classes, teachers and rooms + a fixed set of rules → produce a valid weekly timetable, flag whatever it cannot satisfy, and re-run reliably when inputs change.*

---

## 2. 問題 Problem Statement

- **規模龐大**：約 100 班以上 × 30 課室 × 多校區 × 5 日
- **限制多且互相牽制**：教師不可撞堂、課室不可超額、學生須在報名校區上課、跨校區涉及交通時間、英文 Net 教師另有特別要求
- **每學期重做**：相同的計算每次從頭再來
- **人手容易出錯**：即使人手排出的版本，本身也可能有內部矛盾（例如教師被安排到其無法出勤的日子）

---

## 3. 用家 Users

- **主要用家**：負責排時間表的同事（自助流程：上載 → 檢視 → 微調 → 下載）
- **資料提供者**：各 Program Leader（開科、人數）、行政組（人數、課室）、中心主管（課室）

---

## 4. 輸入 Inputs（一份 Excel，多張工作表）

| 工作表 | 內容 | 必填 |
|---|---|---|
| **Class list** | 每班：科目代號、科目名稱（中／英）、Loading（每週時數）、學生人數 | ✅ |
| **Teacher load table with subject** | 教師 × 各科可教班數（quota）＝ 資格及上限 | ✅ |
| **Centre Room Allocation** | 課室代號、校區、座位容量 | ✅ |
| **Teacher Availability** | 教師 ×（日 × 時段）；不可用格填 `N`，留空即為可用 | ✅ |
| **Net Teachers** | Net 教師名單（標記英文 Net 身分） | 英文科需要 |
| **English Weekly** | 英文教師逐 block 分配的**人手覆寫**；**留空即由系統自動編排** | 選填 |
| **Class list answer** | **V4 全自動模式請留空**；若已填則沿用該 Day／Time／Room（V3） | 選填 |

**時段模型**：標準 2 小時格 `0900-1100 / 1100-1300 / 1400-1600 / 1600-1800`；Loading=4 的科目排連續兩格，Loading=2 排一格。

## 5. 限制 Constraints

### 🔴 硬限制 Hard（違反即編排失敗）

| # | 規則 | 備註／例外 |
|---|------|------|
| H1 | 教師不可於同一時段教兩班 | 永遠強制 |
| H2 | 課室不可於同一時段容納兩班；不可超出座位上限 | 永遠強制 |
| H3 | Core 科上課地點 ＝ 學生報名校區 | 例外：TS→TM（待 Jo 確認 J1）；容量不足時就近校區替補（J8） |
| H4 | 教師每週 Loading 上限 6 班 | **V6 改為軟上限**：超出只發警告，不阻擋 |
| H5 | CC Combine 條件：同科目 ＋ 同語言 | 於 Phase B 檢查 |
| H6 | TKO 校區課堂須於 10:00 或之後開始 | 冷氣費考量 |
| H7 | 教師須具備該科資格，且未超出 Loading | 永遠強制 |
| H8 | 教師同一日不可前往兩個校區 | 軟閘：交通 ≤90 分鐘可跨（發警告）；超過 90 分鐘硬性阻擋 |
| H9 | 學生同一日不可前往兩個校區 | 例外：CSW↔SSP、TW→CSW／SSP |

### 🟡 軟限制 Soft（盡量符合，違反時發警告）

| # | 規則 | 備註 |
|---|------|------|
| S1a | 尊重教師不可用時間 | 最後一步方才放寬並發警告 |
| S1b | 尊重教師校區偏好 | 放寬時發警告 |
| S2 | 避免「天地堂」（同半天空堂超過 2 小時） | **只適用於學生**，不計教師 |
| S3 | 同科多班輪流分佈至不同日子 | 避免集中於某一日 |
| S4 | CC Combine 選擇人數最多的校區 | 平手時選較近者 |

### 🔵 CC Combine 合班邏輯

- **L1**：先排 Core，再為 CC 班尋找「所有相關學生當天在其他校區均無 Core 科」的日子
- **L2**：L1 無解時，改用次多學生的校區重新搜尋；全部失敗則標示為人手處理

### 🟢 英文科／Net 教師特別規則（DAE102）

- 英文科跨全部校區，**共用同一隊教師**；當中部分為 Net 教師（由 Jo 指定，在「Net Teachers」名單標記，不限人數）
- 教師**每 5 週一個 block 輪換**；每學期 3 個 block × 2 學期
- **每個非豁免班每學期至少 1 個 Net block**（假設 1 個 block ＝ 20 Net 小時，待 Jo 確認 J9）
- **豁免班**：CS1、CS2、CS3、CS7（警察 cadet／十月加開班）
- 英文教師同日跨校區交通上限為 **30 分鐘**
- 英文教師可出勤日通常為 **Mon／Tue／Thu**（由 Availability 資料推導）

### 交通 Travel

- 校區之間設交通時間矩陣；H8 上限 90 分鐘，英文科 30 分鐘

## 6. 編排流程 Scheduling Process

```
輸入 Excel
  ├─ Phase 0 : 預排 Cadet 班（固定日子／課室）
  ├─ Phase A : 編排 Core 班（套用 H1–H9, S1–S4）
  ├─ Phase B : 編排 CC Combine 合班（L1／L2／H5／S4）
  └─ 教師分配 : 5-pass 由嚴至寬，每次放寬均發警告
        Pass1 全嚴 → Pass2 放寬科目 quota → Pass3 放寬校區偏好
        → Pass4 放寬週上限 → Pass5 放寬不可用時間
        （H8 交通限制永不放寬）
  └─ 英文科 : 逐 block 自動分配教師（顧及可用時間、Net 要求、30 分鐘交通）
```

同一份輸入 → 同一套規則 → **每次結果一致**（可靠、可重複、可審計）。

---

## 7. 輸出 Outputs

1. **完整時間表**：每班的 Day／Time／Room／教師（Lec1／2／3）
2. **四個檢視**：
   - 日（課室 × 時段）
   - 週·課室（課室 ×（日 × 時段））
   - 週·教師（教師 ×（日 × 時段），撞堂以紅色標示）
   - 月·學期曆（15 週 × Mon–Fri，標示香港公眾假期）
3. **Issues 面板**：所有無法安排或需注意的項目，分類（資料問題／編排衝突／已套用假設）並附建議行動 —— **無法安排者會明確列出，不會隱藏**
4. **可下載 Excel**：班別分配、逐日時間表、英文 Weekly、Issues、15 週學期曆

---

## 8. 改動流程 Amendment Workflow（簡報重點）

當學生人數／開科／教師有變動時：

1. 在輸入 Excel 修改對應欄位（例如某班學生人數、增減某科）
2. 重新上載
3. 系統以**同一套規則**於數秒內重新編排，產生新版時間表
4. 若出現新衝突，會即時於 Issues 面板標示
5. 亦可在畫面上**拖放**手動微調個別班，再下載

重點：**改動是穩定而可重現的** —— 並非每次重新「向 AI 詢問一次、由它猜出答案」，而是修改輸入後再執行同一套邏輯。

## 9. 驗收 Acceptance Criteria

- [ ] 上載一份合規的 Excel，數秒內產生完整時間表
- [ ] 零硬限制違反：無教師撞堂、無課室超額或衝突、學生均在報名校區
- [ ] 所有無法安排的班別全部於 Issues 面板列出並附建議
- [ ] 英文科：每個非豁免班每學期至少 1 個 Net block（或於 Issues 說明無法達成的原因）
- [ ] 四個檢視正常運作；月曆能標示香港公眾假期
- [ ] 修改輸入後重新上載 → 得出一致而更新的時間表
- [ ] 可下載 Excel 供人手作最後微調
- [ ] 非技術用家依 3 個步驟（下載範本 → 填寫 → 上載）即可使用
